- 版: 0.2（2026-10-13）
- 状態: ドラフト。実機で未確認の前提は「要検証」と明記する
- 対象機: RayNeo X3 Pro（ARGF20 / MercuryLiteXR）
- 関連: [workflow.md](workflow.md)（開発手順・検証手順）

## 1. 目的とスコープ

| 項目 | 内容 |
|---|---|
| 目的 | プラモデル組み立てを、両手を空けたまま眼鏡で誘導する |
| 対象 | **プラモデルのみ**。F_PANEL / PC 作業には広げない |
| 利用形態 | 眼鏡単体。**iPhone コンパニオンは作らない** |
| 手順の入手 | PC で説明書を JSON 化し、眼鏡へ配置する |
| 長期の理想 | 実物上に次パーツ／スロットを重ね、誤りは赤で警告する |

### 1.1 価値の優先順位

1. **手順を両手フリーで進める**（HUD + 音声）。MVP の核心。
2. **今の手順の図とパーツ番号を見せる**。
3. **作業の合否を確認する**（イベント時のみ）。
4. **実物にワールド固定でマーカーを置く**（空間）。

1 と 2 だけで価値が成立する状態を、先に作る。3 と 4 は、前提の検証が終わるまで約束しない。

### 1.2 やらないこと

- プラモ以外の用途への拡張
- iPhone 連携
- 現行 APK への OpenXR loader / `ar_mode` / XR Plugin の追加
- 説明書の全頁の常時投影（FOV 約 30° では実物が見えなくなる）
- 毎フレームの VLM 推論
- 説明書の再配布（個人利用の範囲に限る。§9）

## 2. 機体と技術的制約

| 項目 | 内容 | 確度 |
|---|---|---|
| ディスプレイ | MicroLED 導波路。黒 `#000000` は透明。UI は緑 `#00FF66` を中心にする | 確認済み |
| 解像度 | SBS 1280×480（片眼 640×480）、FOV 約 30° | 公開情報 + 実機 |
| カメラ | RGB（IMX681）と VGA モノクロ（SLAM 用） | 公開情報 |
| `WebCamTexture` | 白黒魚眼のみ取得できている。RGB は経路未確定 | 確認済み / RGB は要検証 |
| 音声 | `SpeechRecognizer` はウェイクワード専用で使えない。**Vosk オンデバイス日本語**が実働 | 確認済み |
| ギャラリー | `DCIM/Camera` の JPEG のみ表示される | 確認済み |
| 電池 | 245mAh（レビュー報告） | 要検証 |
| 公式 SLAM | XR Plugin + ヘッドモード SLAM + `EnableSlamHeadTracker`。UI は World Space | 公式ドキュメント |

### 2.1 前提として扱わないこと（要検証）

| # | 主張 | 状況 |
|---|---|---|
| V1 | 「公式 SLAM 中は眼鏡カメラが使えない」 | 出典は X2 レガシー側の記述。**X3 Pro は未確認** |
| V2 | 「6DoF は OpenXR loader が必須」 | `libRayNeoXRApiLayerClient.so` の `dlopen` 失敗までしか確認していない。SIGSEGV の原因が loader 本体か XR 初期化かは**切り分け未了** |
| V3 | 「白黒魚眼で確認判定ができる」 | 向き違い・色違い・ゲート処理は未検証 |
| V4 | 「RGB カメラを loader なしで取れる」 | 経路未確定（Camera2 など） |
| V5 | 「SLAM 状態でシーン往復できる」 | コミュニティ報告で、3DoF から 6DoF へは一度だけ。往復で不安定 |

仕様書の「できる／できない」は、V1〜V5 の検証結果で更新する（[workflow.md](workflow.md) §5）。

## 3. システム構成

### 3.1 モード

| モード | 内容 | 状態 | 配布 |
|---|---|---|---|
| **ガイド** | 3DoF 相当の HUD + 音声 + 手順 JSON + 図パネル | 実装済み（図パネルは未） | 現行 APK |
| **確認** | 短時間カメラ → 静止画で合否判定 | 未実装 | 現行 APK に追加（V3・V4 の結果次第） |
| **空間** | ワールド固定マーカー（World Space + SLAM） | 未着手 | **別 APK**（検証後に統合を判断） |

### 3.2 現行 APK の安全経路（変更禁止）

- Unity 2022.3.62f3 URP、`Assets/Gude.unity` のみをビルドする
- 2D Overlay HUD、左右 SBS（`BinocularSbsUi`）
- `com.rayneo.mercury.app=true`、`singleTask`、`AR_APP`、landscape
- `ar_mode` なし。OpenXR loader の AAR は Exclude Android。XR の `InitManagerOnStart` は 0
- 音声は Vosk（`KeywordSpeechPlugin`）。カメラは `WebCamTexture`
- 保存: `persistentDataPath` 配下 + `DCIM/Camera`

## 4. 機能仕様（ガイドモード）

### 4.1 表示（3 段 HUD）

| 帯 | 内容 |
|---|---|
| 上 10% | `Step n/m` と `partIds` |
| 中 80% | 作業指示（`instruction`） |
| 下 10% | 操作ヒント（`hint`）または音声の状態 |

- 中央をカメラ映像などで塞がない。
- 緑枠（`KitWorldHint`）は §4.4 のとおり「注目パネル」に位置づけを変える。

### 4.2 音声コマンド

| コマンド | 語彙 | 動作 |
|---|---|---|
| 次へ | 次へ、次、つぎ、進む | 次ステップ。準備中はスキップ |
| 戻る | 戻る | 前ステップ。完了画面からは最後へ |
| もう一度 | もう一度 | 現在の指示を再表示 |
| 原点 | 原点、ここ、記録 | 原点を記録（準備中のみ） |
| 確認 | 確認 | **新規**。確認モードを呼ぶ（V3・V4 が通るまで無効） |

認識したら、ヒント行に「了解：…」を約 1.2 秒出す。

**誤進行の対策（新規）**
- 作業音（ニッパー、やすり）で誤認識しやすいので、「次へ」の誤進行は**戻る 1 回で必ず直前に戻れる**ことを保証する。
- 連続して 2 秒以内に同じコマンドが来たら、後者を無視する（二重進行の防止）。
- 将来、確認が要るステップ（接着など）では、「次へ」の前に聞き返す（任意）。

### 4.3 原点キャリブレーション

- 起動直後は準備状態。キット全体を約 2 秒静止して見ると JPEG を保存する。
- 保存先は `persistentDataPath/Calibration/kit_anchor.jpg` と `DCIM/Camera`（`IMG_yyyyMMdd_HHmmss_FixLens.jpg`）。
- 「次へ」でスキップすると、原点なしで進む。暗い、権限なし、カメラが開けない場合も、**失敗を表示してスキップ**する。

### 4.4 緑枠（KitWorldHint）の位置づけ

現行は、Overlay をジャイロ角速度の積分で逆補正する**回転だけの近似**で、ドリフトし、平行移動には追従しない。したがって次の扱いとする。

| ルール | 内容 |
|---|---|
| 約束しない | 枠は「実物のこの位置」を保証しない。仕様上は「注目領域の目安」 |
| 範囲外 | 端にクランプしない。視線が離れたら消し、戻ったら再表示する |
| ドリフト | 一定時間で再ロックを促す。目標値は §8 |
| 内容 | 枠の中にパーツ番号（`partIds`、なければ「作業位置」）。将来は図の切り出しを表示 |
| カメラ画像追跡 | ドリフト補正としてだけ弱く混ぜる。主表示にしない（遅延と上下反転が出た） |
| 軸（実機確定） | 右を向く = `gyro.x` → 枠は左へ。下を向く = `gyro.y+z` → 枠は上へ。約 24 px/deg |

### 4.5 進行状態の保存（新規）

- `persistentDataPath/Procedures/progress.json` に `kitId`、`currentStepIndex`、`updatedAt` を保存する。
- 起動時、同じ `kitId` なら続きから再開するか、先頭からかを選べる（音声「最初から」「続きから」）。
- クラッシュや再起動で、先頭に戻らないことを受け入れ基準とする。

### 4.6 失敗時の動作

| 状況 | 動作 |
|---|---|
| カメラ権限拒否 | 原点なしで進み、ヒントに表示する |
| Vosk モデル展開失敗 | 「音声が使えません」を常時表示し、タッチパッドや Space の代替操作を案内する |
| 手順 JSON が不正 | 理由をヒントに出し、Resources の既定にフォールバックする |
| 初回の Vosk zip 展開 | 数秒かかる。「音声を準備中」と表示する |

## 5. 手順データ（ProcedureDocument）

### 5.1 現行スキーマ（v1）

```json
{
  "kitId": "sample-plamodel-01",
  "kitName": "サンプル：小型ロボット",
  "source": "hand",
  "steps": [
    {
      "id": "s01",
      "sourcePage": 2,
      "partIds": ["A-1"],
      "instruction": "ランナーAから胴体 A-1 をニッパーで切り出す",
      "hint": "「次へ」「進む」　「戻る」　「もう一度」",
      "stepNumber": ""
    }
  ]
}
```

### 5.2 拡張スキーマ（v2）

後方互換を保つ。v1 の JSON は `schemaVersion` がなければ v1 として読む。

| フィールド | 型 | 意味 |
|---|---|---|
| `schemaVersion` | int | 2 |
| `steps[].type` | string | `cut` / `trim` / `fit` / `glue` / `wait` / `paint` / `check` |
| `steps[].durationSec` | int | `wait` のときのタイマー（例: 乾燥待ち） |
| `steps[].figure` | object | 出典図の参照。`image`（相対パス）と `crop`（x, y, w, h を 0〜1 の正規化） |
| `steps[].target` | object | 指す対象。`kind`（`runnerPart` / `slot`）、`label`、任意の `hintRegion`（原点基準の相対座標） |
| `steps[].expect` | object | 確認用の期待状態。`description`（自然文）と任意の `checks[]` |
| `steps[].confirm` | bool | 「次へ」の前に聞き返すか |

- `wait` ステップ（例: サンプルの s06「置いて触らない」）は `durationSec` を持ち、HUD にカウントダウンを出す。
- `expect` が空のステップは確認の対象外。
- `target.hintRegion` は、**空間モードの前に、図パネルで使う**（枠の位置を約束しない）。
- JSON パースは、`JsonUtility` で足りる範囲を超えるなら、導入するライブラリを workflow の判断事項とする。

### 5.3 取り込み・配置

| 工程 | 内容 |
|---|---|
| 作成 | PC で説明書を OCR または手入力 → v2 JSON。Editor の `ProcedureImporterWindow` を拡張する |
| 検証 | PC 側のビューアで、各ステップの `figure.crop` と `target` を目視確認する（OCR の誤りは PC で直す） |
| 配置 | `adb push` で `persistentDataPath/Procedures/active.json` へ。非エンジニア向けの代替（USB ストレージ、QR など）は未決（§10） |
| 優先順位 | `active.json`、Inspector の TextAsset、Resources の既定、フォールバック |

## 6. 確認機能（イベント駆動）

### 6.1 トリガー

- 原点ロック直後
- ステップ変更時（`type` が確認に向くものだけ）
- 音声「確認」

毎フレームの推論はしない。

### 6.2 検出対象の定義（MVP 案）

| 誤りの種類 | 判定できそうか（要検証 V3） |
|---|---|
| パーツ番号違い | 低い（白黒魚眼では文字を読めない可能性） |
| 向き違い（腕の左右） | 中（形状次第） |
| 切り出し・ゲート処理の有無 | 低〜中（解像度次第） |
| 接着後の乾燥待ち | 不要（`wait` タイマー） |

**方針**: V3・V4 の結果が出るまで、確認機能は仕様上「予約」とする。最初は、ステップごとの `expect.description` を人間が読める形で表示するだけ（「このように見えていますか」）から始める。

### 6.3 実行基盤

- 静止画 1 枚を PC またはクラウドの VLM に送る。通信不能時は、ローカルで「確認できませんでした」を出して進行を妨げない。
- プライバシー: 送信する画像は作業面のみ。顔や室内全体を含めない前提を、撮影ガイドで示す。保存・送信の ON/OFF を設定にする。

## 7. 空間モード（別 APK）

### 7.1 目的

「実物のこの位置に印を残す」を、公式 SLAM で成立するか確かめる。現行 APK とは**統合しない**。

### 7.2 構成（公式ドキュメントに準拠）

- XR Plugin プレハブ、ヘッド制御モード SLAM
- `Algorithm.EnableSlamHeadTracker()`（有効化後、約 1 秒静止）
- 状態は `Algorithm.GetSlamStatus()`（初期化／成功／失敗）
- 姿勢は `HeadTrackedPoseDriver.OnPostUpdate` の `Pose`
- UI は World Space Canvas。終了時は `DisableSlamHeadTracker()`

### 7.3 既知のリスク

- 状態が `INITIALIZING` から進まない報告がある（OS 3.26.4.28 / runtime 1.1.7.9 / ARDK 1.1.2）。
- 3DoF シーンから 6DoF シーンへは一度だけ、という報告がある。
- 公開されている空間アンカー保存 API は確認できていない。**再起動で座標は失われる前提**で、原点の再取得を設計に入れる。
- SLAM 有効中にカメラが使えるか（V1）で、確認モードとの併用可否が決まる。

## 8. 受け入れ基準

| 項目 | 基準（初期値） | 計測 |
|---|---|---|
| 枠の追従 | 頭を振って目視で、遅れを感じない（目安 100ms 以内） | 実機観察 + ログ |
| ドリフト | 静止 1 分で、枠の移動が一定範囲内（初期値は workflow で実測してから確定） | 実機 |
| 範囲外 | 枠の一部が端に残らない | 実機（確認済み） |
| 音声 | 作業音ありで、誤進行 0（10 分の作業で） | 実機 |
| 音声の応答 | コマンドから HUD 更新まで 1 秒以内 | ログ |
| 進行保存 | アプリ強制終了後、同じステップから再開できる | 実機 |
| 電池 | 連続 60 分以上（HUD + Vosk + 原点のカメラ） | 実機 |
| 発熱 | 連続使用で不快な熱さにならない | 実機 |
| 視認性 | 明るい作業机で、緑が読める | 実機 |
| 原点 | 2 秒静止で記録できる。失敗時はスキップを選べる | 実機 |

数値は初期値。実測してから改訂する。

## 9. 運用・法務・安全

- **配置導線**: 現状は `adb push` が前提。非エンジニア向けの導線は未決（§10）。
- **OCR 修正**: 眼鏡では編集しない。PC 側のビューアで直す。
- **著作権**: 説明書の画像は、個人利用の範囲で端末内に置く。再配布しない。
- **安全**: ニッパーやナイフを使う作業中は、HUD が手元の視界を塞がないこと（中央を空ける）。連続作業の目安時間を超えたら休憩を促す（任意）。
- **焦点**: 眼鏡の見かけの結像距離と手元（30〜50cm）にずれがある。長時間の評価を、実機の確認項目に含める。
